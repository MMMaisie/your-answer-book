# 你的答案之书 · 六十四象 v4

这是对原 Flask 网站的模块化改造，继续使用 DeepSeek 和 Stripe。请部署整个项目目录，不能只替换一个 Python 文件。

## 本次完成

- 64 卦全部有独立的古典画面、卦名、主题、画意说明；画面来自四幅 4×4 原创 AI 图集，网页按位置显示每一张，不依赖外部图片网站。
- 手动掷币或逐次点击系统掷币。六爻从下往上组成本卦，动爻再构成变卦。无动爻只显示本卦。不是把六次掷币当成六个独立六十四卦。
- 自动掷三枚独立硬币，使用浏览器密码学随机数，正面个数概率为 1:3:3:1。
- 文王64卦序、八宫、纳甲、六亲、世应、六神、伏神、日月与旬空；变爻六亲按本卦宫五行计算。
- 海外当地时间按所选 IANA 时区换算北京时间；月按节气，日按零点换日；不校正真太阳时。夏令时跳时/重复时段拒绝歧义输入。
- 免费初判完整有用：直接回答、具体凭据、验证条件、宜忌。去掉星级、伪概率、情绪推断、故意吊胃口的广告，以及固定套话。
- 免费只调用免费解读；付款验证后，用户主动点击才生成完整解读。GET/刷新不消耗新的模型调用。
- 未付款 HTML 中没有完整解读；AI内容作为纯文本安全显示。
- 私密链接使用随机访问凭证；公开分享只带卦画和通用卦义，不带问题/初判/付费文字。分享可撤销。
- 免费限额默认同浏览器每日3次、地址摘要每日12次、全站每日100次；计数7天后清理。失败也计入请求上限，避免重复失败无限调用。相同浏览器、同问题/时间/时区/六次结果的同版本请求命中缓存。
- AI失败明确提示，不再生成假装个性化的固定模板。
- 支付回调校验签名，支持 completed 和 async_payment_succeeded，核验本机订单、种子、价格配置，重复回调幂等。
- 默认中文；英文入口与英文AI输出保留。卦名、卦盘与新增文化解释主要为中文。

## 本地运行

```bash
python -m pip install -r requirements.txt
python app.py
```

本地打开 http://127.0.0.1:5000 。不配置密钥也能浏览画册、起卦动画和 `/demo` 教学示例；提交真实问题会明确提示服务未开启。
真实解读需要环境变量 DEEPSEEK_API_KEY，不要把密钥贴到聊天或源码中。本地会生成只供本地使用的 `.local-secret`，生产必须配置长期不变的 FLASK_SECRET_KEY。

## 更新现有 Render 网站

1. 从 Render 当前服务确认关联的仓库、分支和项目根目录；先备份现有数据库。
2. 将本目录文件放入关联仓库的服务根目录；使用 `app.py`、`hexagrams.py`、`templates/` 和 `static/` 整套文件。
3. Build Command: `pip install -r requirements.txt`
4. Start Command: `gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120`
5. Health Check: `/healthz`
6. 保留原 DeepSeek 和 Stripe 环境变量；参考 `.env.example` 补充 FLASK_SECRET_KEY、PUBLIC_BASE_URL、SUPPORT_EMAIL、COOKIE_SECURE、TRUST_PROXY、DB_PATH。
7. 如果启用付费，请把 SQLite 放到真正的持久磁盘上，例如 `/var/data/readings.db`，然后设置 `STORAGE_DURABLE=1`。先确认数据库确实在挂载目录中。这个标志不是购买磁盘的操作，也不会自动创建数据库服务。
8. Stripe Webhook 地址仍为 `你的域名/stripe/webhook`，订阅 `checkout.session.completed` 和 `checkout.session.async_payment_succeeded`。使用有效的对应模式 webhook secret。
9. 先以 Stripe 测试模式跑完整付款和异步回调，核实账户支持你的具体业务及支付方式，再开放真实付款。金额与币种来自 Stripe Price ID，网站不再硬写 AU$1.99。
10. 免费浏览与解读可先上线；缺少收款配置、支持邮箱或持久存储标志时，付款按钮不会出现。

`render.yaml` 是新服务的可选模板，选择了付费实例与磁盘；它没有被执行，不会自动更改当前服务或产生费用。更新现有服务优先按上面的步骤，不必新建。

Render 免费 Web Service 的本地 SQLite 会在重启、重新部署、休眠时丢失，不能把付费权限放在临时文件系统。要么使用持久磁盘，要么将存储改为外部数据库；本版本使用前者，没有实现 PostgreSQL。

## 老数据迁移与链接

启动时增加列与新表，保留原 readings/payments 数据。旧的可猜测/缓存式 `/reading/<seed>` 链接不再允许陌生会话直接读取私人内容。新记录用 `/r/<随机凭证>`。
旧记录没有所属浏览器，需由运营者核验后通过数据库里的新 access_key 发还客户；不要公开导出这些凭证。老付费文本保留在数据库，但不会直接当成新版解读显示；付款权益保留，取得新链接后可生成新版。旧 Checkout Session 若不是 v4 本地订单，不能走 v4 成功回调自动恢复访问。

迁移前建议备份数据库。旧数据库已有同 seed 或 Stripe session 唯一约束仍保留。不要同时启动旧程序写入新数据库；不要把数据库提交到仓库。
